# Zently implementation plan

Goal: create a runnable local messenger from the approved Zently design, then publish the source to the user's GitHub.

Architecture: dependency-free Node HTTP server, persistent JSON store, HttpOnly local sessions, server-sent events, browser modules and WebRTC signaling. No external SMS provider is configured. The server binds to localhost by default.

Spec: DESIGN.md, UX-CONTRACT.md, and the approved Figma file TaVwjYFxyys7YGOIYUEzap.

- [ ] Test first: authentication validation, self-only saved messages, membership checks, idempotent sends, restart persistence.
- [ ] Implement store and API, with bounded bodies, challenge expiry, request origin checks and cookie sessions.
- [ ] Implement responsive approved visual language, demo entry, registration, chat search, composer, saved messages, attachments and profile.
- [ ] Implement clearly distinguished demo call preview and WebRTC calls between connected real accounts.
- [ ] Run Node checks/tests and browser scenario checks; fix observed defects.
- [ ] Initialize Git, create private Zeeefir/zently, upload verified sources and verify the remote.
- [ ] Start and open the local website; provide startup instructions and explicit production limitations.

Review focus: malformed input; cross-user saved-message access; stale or repeated code verification; duplicate sends; denied media permissions and cleanup after a call.
